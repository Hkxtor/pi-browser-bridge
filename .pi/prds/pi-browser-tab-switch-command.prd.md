# PRD: Pi 浏览器活跃标签页切换命令

## Problem
Pi Browser Agent 当前可以列出 Chrome 标签页，并允许浏览器工具显式接收 `tabId`，但用户缺少一个直接、可视化的入口来选择并切换当前操作目标。用户通常需要先调用标签页列表工具、读取编号，再在后续操作中手动指定标签页；浏览器桥尚未连接时，恢复路径也不够集中。

需要在 Pi 侧提供 `/tab` 斜杠命令：尝试连接现有 Chrome 扩展，在交互式选择器中展示可用标签页，并将用户选择的标签页激活为后续浏览器操作的默认目标。

## Goals
- 在 Pi 交互模式中提供 `/tab` 命令和键盘可操作的标签页选择器。
- 执行命令时复用现有浏览器 Transport，进行有界连接与就绪等待。
- 选择后激活对应 Chrome 标签页，并使未显式传入 `tabId` 的后续 `browser_*` 操作默认指向该标签页。
- 提供明确的成功、取消、断连、空列表和标签页失效反馈。
- 命令流程确定性执行，不触发 LLM 推理。

## Non-Goals
- 不负责启动 Chrome、自动安装或启用 Chrome 扩展。
- 不将 Chrome 窗口提升到操作系统前台。
- M1 不支持 Firefox、Safari、Edge 或 Brave 等其他浏览器。
- M1 不支持 `/tab <id|标题|URL>`、`/tab next` 或 `/tab prev` 参数模式。
- M1 不跨 Pi 重启持久化所选标签页。
- 不改变网页内容，也不绕过现有浏览器权限与安全策略。

## Users And Workflows
- User: 使用本仓库 Chrome 扩展和 Pi Browser Agent 的本地 Pi 操作者。
- Workflow: 用户输入 `/tab` → Pi 连接或等待浏览器桥就绪 → 获取可用标签页 → 展示带当前活跃状态的选择器 → 用户选择标签页 → Chrome 激活该标签页，Pi 将其作为默认浏览器目标 → Pi 显示切换结果。
- Workflow: 用户按 Esc 取消 → 保持原标签页与 Pi 目标不变。
- Workflow: 扩展未连接或标签页已关闭 → Pi 显示可恢复错误及下一步操作，不崩溃、不无限等待。

## Requirements
| ID | Requirement | Priority |
|---|---|---|

| R2 | `/tab` 必须直接执行命令处理逻辑，不向 LLM 发送提示或启动 Agent turn。 | P0 |
| R3 | 命令必须复用现有 Transport 的连接及 `waitForReady` 语义，并遵守已配置的就绪超时。 | P0 |
| R4 | 连接就绪后，命令必须通过现有标签页列表能力获取当前可操作标签页，不另建平行的数据来源。 | P0 |
| R5 | 选择器必须展示经过截断和控制字符清理的标题、URL，以及当前活跃标签页标识；内部使用稳定 `tabId` 作为选择值。 | P0 |
| R6 | 选择器必须支持上下键导航、Enter 确认和 Esc 取消；取消不得产生标签页切换副作用。 | P0 |
| R7 | Chrome 扩展/桥协议必须提供按 `tabId` 激活标签页的能力，并返回最终标签页的 `tabId`、标题、URL 和活跃状态。 | P0 |
| R8 | 切换成功后，所选标签页必须成为其 Chrome 窗口内的活跃标签页，并成为后续未显式指定 `tabId` 的 Pi 浏览器工具默认目标。 | P0 |
| R9 | M1 不得调用操作系统级窗口聚焦能力；成功提示不得宣称 Chrome 窗口已前置。 | P0 |
| R10 | 断连、连接超时、无可用标签页、标签页在选择后关闭、扩展不支持激活能力等情况必须返回明确且可操作的提示。 | P0 |
| R11 | 标签页在列出后失效时必须返回 `tab_not_found` 或等价稳定错误，不得静默切换到其他标签页。 | P0 |
| R12 | 必须增加命令处理、取消路径、错误映射、协议激活和后续默认目标行为的自动化测试，并补充一次真实 Chrome 联测步骤。 | P1 |
| R13 | 使用文档和排障文档必须说明 `/tab` 的使用方式、连接前提和“不前置操作系统窗口”的边界。 | P1 |

## Acceptance Criteria
- [x] Chrome 扩展已连接且存在至少两个可操作标签页时，输入 `/tab` 会打开选择器，并正确标记当前活跃标签页。
- [x] 选择一个非活跃标签页后，Pi 显示包含标题或 URL 的成功提示；再次执行 `/tab` 时该标签页显示为活跃。
- [x] 切换成功后，不传 `tabId` 调用 `browser_page_text` 或 `browser_page_snapshot` 时，读取的是刚选择的标签页。
- [x] 在选择器中按 Esc 后，命令安静退出，原活跃标签页和默认目标保持不变。
- [x] 浏览器桥尚未就绪时，命令按配置进行有界等待；超时后显示扩展安装、启用或重连建议，且不会无限挂起。
- [x] 没有可操作标签页时，命令显示明确提示且不打开空选择器。
- [x] 标签页在列表展示后、确认前被关闭时，命令返回稳定错误且 Pi 会话继续可用。
- [x] 页面标题或 URL 含控制字符或超长文本时，选择器仍安全、可读，并保持终端布局稳定。
- [x] 命令不会启动 LLM 请求，也不会尝试将 Chrome 窗口置于操作系统前台。
- [ ] 相关单元测试、传输层集成测试通过，并完成文档化的真实 Chrome 冒烟验证。（自动化与部分 RPC/真实 Chrome 主链路已通过；原生 TUI 键盘、前台焦点和真实关闭竞态仍待人工验收。）

## Risks
| Risk | Mitigation |
|---|---|
| Chrome 每个窗口都可能有一个活跃标签页，跨窗口选择容易产生“当前标签页”歧义 | 以用户选中的 `tabId` 作为 Pi 默认目标；成功提示说明目标标签页及其窗口语义，不承诺操作系统窗口前置 |
| 标签页可能在列表获取后被关闭或导航 | 激活时重新校验 `tabId`；失效时返回稳定错误，不自动选择其他标签页 |
| 浏览器扩展冷启动或断连导致命令看似无响应 | 复用有界 `waitForReady`，显示等待状态，并在超时后给出可恢复建议 |
| 页面标题或 URL 注入终端控制字符、破坏布局 | 渲染前清理控制字符、限制显示长度，并保留原始 `tabId` 作为内部标识 |
| `/tab` 与其他扩展命令重名 | 在实现与测试中检查命令注册结果；若发生冲突，记录 Pi 的后缀行为并在文档中说明 |
